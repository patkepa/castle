# Castle configuration

This file is Castle's checked-in, portable configuration. Relative paths are
resolved from the directory containing this file. You can edit these values
without changing application source code.

## Application

- `application.name` controls the desktop application and executable name.
- `application.bundle_id` must be a reverse-DNS identifier unique to your
  packaged desktop application.

## Library

- `library.path` points to the Markdown library Castle should build for the web
  development and static build workflows.
- `library.repository_path` points to the repository containing that library.
  Castle uses it only for repository-aware metadata such as original stash
  creation dates.

The defaults use the synthetic `example_library/` included in this repository.
Point a local override at your own library; absolute paths and paths relative
to this file are both accepted.

## Owner

- `owner.note_id` optionally identifies the note used for the relationship
  graph's root. Use its library-relative note ID without `.md`, for example
  `people/alex_morgan`. Leave it empty when no owner note should be linked.
- `owner.display_name` is the fallback root label.
- `owner.avatar_url` is the optional fallback avatar URL. Prefer a library asset
  URL generated by Castle, and leave this empty when no avatar is needed.

For machine-specific paths or private identity values, copy this file to
`CONFIGURATION.local.md`. That file is ignored by Git and overrides matching
frontmatter values from this file. Never put secrets in either configuration;
API keys belong in the ignored `.env` file.
